# 调研 14：v0.4 极简重构详细设计（服务端 / 客户端 双模式 · 零设置）

- **性质**：产品 + 技术详细设计（界面信息架构完全重做；技术底座沿用 v0.3 已实现能力）
- **日期**：2026-09-30
- **输入**：用户对 v0.3 成品的反馈（原话归纳，见 §1）——"界面太多了，设置的
  项目太多了……完全都没有理解到我的意思"。用户口述了理想流程全文，本文
  **逐条对齐并只做这一件事**。
- **取代关系**：修订 [调研 13](13-zero-config-redesign.md) 的 §3（产品设计）与
  §4.8（UI 增量）；13 的技术章节（§4 配对/装队列/多打印机、§5 检查点与日志）
  **继续有效且已实现**，本文只增改不推翻。决策收敛见
  [ADR-0011](../adr/0011-minimal-two-mode-ui.md)。
- **现状锚点**：commit `4b485fb`（v0.3 已全部实现：角色向导、4 位码配对、
  自动装系统队列、多打印机、logx）。文中 `file:line` 基于此，实施时复核。

## 0. 一句话方案

装完 dyj，右下角托盘常驻。点开管理页，**整个产品只有两张卡：「服务端」「客户端」**。
服务端进去：本机打印机自动列出来（默认全选）→ 点一下「一键共享」→ 完成后
**永远停在这一页**（配对码大字 + 连上的电脑 + 最近打印），后台自行运行。
客户端进去：局域网里共享的打印机自动列出来 → 点一下 → 输服务端显示的
**4 位码** → 自动装成系统队列，WPS/Word/记事本里直接可见可打，dyj 不中转。
**没有网络设置页、没有打印机管理页、没有端口/URI/驱动，没有"高级"——
一切自动适配；技术信息只存在于一个"帮助"页里，供出问题时看。**

## 1. 用户要求逐条对齐（本设计的验收尺度）

| # | 用户原话（归纳） | v0.4 落点 | 章节 |
| --- | --- | --- | --- |
| 1 | 服务端、客户端做成同一个东西 | 单二进制不变；界面直接以「服务端/客户端」两个方向呈现 | §3.1 |
| 2 | 进去引导只有两个方向：服务端 / 接收端 | 首页 = 两张大卡，无其他入口 | §3.2 |
| 3 | 服务端自动扫描所有打印设备；一键共享全部或勾选共享；设置完毕即后台自行运行 | 挑选态默认全选 +「一键共享」；完成后原地变主页态，服务常驻自愈 | §3.3、§4 |
| 4 | 服务端显示 4 位数字，客户端输入 4 位配对 | 配对码在服务端主页大字常驻 + 托盘菜单可见；客户端点添加时弹出 4 格输码 | §3.3、§3.5 |

## 2. v0.3 界面体检：到底多在哪里

### 2.1 入口与导航

现状打开管理页是一个**带 7 项侧栏的后台控制台**
（`pkg/admin/web/components/dyj-sidebar.js:7-15`：状态 / 设置向导 / 添加打印机 /
打印机 / 网络 / 作业 / 日志），8 条 hash 路由
（`pkg/admin/web/app.js:16-25`）。对"共享一台打印机"这个目标来说，这是一个
网管工具的信息架构，不是家用工具的。

### 2.2 逐页元素清单与裁决

| 页面 | 现状元素（证据） | 裁决 |
| --- | --- | --- |

| 网络页 `#/network` | **端口 / TLS 端口 / mDNS 开关 / 主机名 / 高级(监听接口)** + 保存 `page-network.js:28-41` | **删除整页**：全部自动化（§4）；仅 CLI/`service.json` 保留 |
| 作业页 `#/jobs` | 三段切换 + 作业表 + 取消 + 30 秒自刷 `page-jobs.js` | **降级**：服务端主页"最近打印"8 行（只读） |
| 日志页 `#/logs` | SSE 日志直播 `page-logs.js` | **并入帮助页**（折叠） |

### 2.3 病根：三个"多"

1. **导航多**：7 项侧栏让用户每次进来都要做一次"我在哪、该点哪"的决策。
   正确形态是**角色即主页**——服务端机器打开就是服务端页，根本没有导航。
2. **术语多**：URI、后端名、队列 key、端口、TLS、mDNS、监听接口、lpadmin
   命令——这些全部是工程视角的直接暴露。
3. **设置多**：网络页 5 个可改字段全部属于"自动适配"的范畴（§4），一个都不该
   让普通用户看见。

## 3. v0.4 信息架构

### 3.1 总览：8 路由 → 4 路由，侧栏删除

| v0.3（8 路由 + 7 项侧栏） | v0.4（4 路由，无侧栏） |
| --- | --- |
| `#/setup` 角色选择 | `#/` 首页（未配置态） |
| `#/share` 共享向导 + `#/status` 状态页 | `#/server` 服务端页（挑选态 / 主页态） |
| `#/add` 添加向导 + `#/status`（use 角色） | `#/client` 客户端页（添加流 / 主页态） |
| `#/printer` `#/network` `#/jobs` `#/logs` | `#/help` 帮助与诊断（唯一技术信息区） |

页面间跳转关系**只有四条**：

```
        （未配置）
   ┌──「服务端」→ #/server
 #/ ─
   └──「客户端」→ #/client

 #/server ←→ #/client   （页脚小链接互跳，改主意用）
 任意页 ── 右上角 [?] ──→ #/help
```

旧 hash（`#/status` 等）301 式重定向到新路由，保住书签（§7.4）。

**角色判定**：服务端渲染哪个主页由 `GET /admin/api/config` 的 `role` 决定
（share → server 页，use → client 页，both → server 页 + 页脚一行入口，§9-Q1，
`""` → 两卡片首页）。这是 v0.3 已有的字段，零后端改动。

### 3.6 文案规范（硬约束）

1. **禁用词**（用户可见界面一律不得出现；帮助页只读区除外）：
   `URI / URL、端口、后端、队列名、key、mDNS、Bonjour、IPP、token、
   host / IP（正文）、驱动、监听接口、TLS`。
2. **人话映射表**（状态与错误的唯一出口，接 §6 检查点）：

| 技术 event / reason | 界面只能说 |
| --- | --- |
| `mdns.announce` 失败 | "局域网里可能看不到这台电脑：多半是防火墙，点 [开始自检]" |
| `pair.attempt ok=false` | "码不对，还剩 N 次机会" |
| `pair.lock` | "试的次数太多啦，请 M 分钟后再试" |
| `queue.install rc≠0` | "安装没成功，Windows 可能要点一下'是'允许；再试一次" |
| `queue.verify` 失败 | "系统里没出现这台打印机，点 [重试]，还不行就 [导出诊断包]" |
| `deny.ipp`（token 失效） | "这台打印机需要重新连接（可能被服务端移除了）" |
| reasons=paper-out 等 | 缺纸 / 卡纸 / 已暂停 / 盖板未合（逐项表驱动） |

3. 数字词只用两个：**4 位配对码**和**台数**。不出现端口号、超时秒数等
   （配对码倒计时是例外，格式"9 分 12 秒后更换"）。

### 3.8 安装 → 可打印的完整时间线

**安装器路径（推荐，管理员权限只在这一刻）**：

```
点「完成」→ 浏览器自动打开 #/（两卡片）→ 之后的动作见 §5
```

**绿色路径（免安装）**：双击 `dyj.exe` → 控制台窗 + 浏览器自动打开 `#/`，
行为完全一致；完成页提示"安装 dyj 可获得开机自启"。

两条路径在第 1 秒后**零差别**——这是对 v0.3 首启死锁修复的保持项。

## 4. 自动化行为规格：每一项"用户不设置"的东西

用户不设置 ≠ 没有策略。每一项都要有自动策略、失败兜底、检查点、用户话术
四件套。**这张表是"自动适配"的契约，也是 §6 检查点的索引。**

| # | 用户以为没有的东西 | v0.4 自动策略 | 失败兜底（用户可见） | 检查点 |
| --- | --- | --- | --- | --- |
| A1 | 端口 | 固定 6631；被占自动 +1 探测空闲 | 管理页顶一条黄字"端口被占，已用 NNNN"（帮助页可见实际值） | BOOT-1 |
| A2 | 防火墙 | 安装器静默建 TCP/UDP 规则 | 自检项给一键修复指引 | SHARE-4 |
| A3 | mDNS 宣告 | 永远开、逐网卡宣告、冲突自动加序号 | 黄条"局域网可能看不到这台电脑"+ 自检 | SHARE-4/5 |
| A4 | 打印机枚举 | Windows EnumPrinters / Unix `lpstat`；虚拟打印机默认隐藏 | 列表空 → "显示虚拟打印机"小链接 | SHARE-1/2 |
| A5 | 驱动（客户端） | 一律 Microsoft IPP Class Driver / `lpadmin -m everywhere`，系统自选 | —（无需任何选择） | USE-4 |
| A6 | 队列名 | 取服务端打印机人读名；重名自动 ` (2)` | 静默处理，仅日志 | USE-4 |
| A7 | 连接地址 | URI host 用 `.local` 优先，回退 IP；失配自动删旧重建 | 客户端页状态列"服务端不在线，点此重新扫描" | USE-5 |
| A8 | 配对码生命周期 | 4 位数字、10 分钟滚动轮换、每 IP 限速锁定 | 界面只说"N 分钟后再试" | PAIR-1..4 |
| A9 | 配置热生效 | 进程内拆除重建，HTTP 不断 | "有作业没打完，稍后自动继续" | CFG-1/2 |
| A10 | 后台常驻 | SCM 服务 + 崩溃自愈 + 开机自启；接收端**无常驻** | 托盘 tooltip "服务未运行" | BOOT-2 |
| A11 | 打印机探测 | 共享前逐台 `OpenPrinterW` 试开 | 行内红字"这台打不开：<原因>"，不阻塞其他行 | SHARE-2 |

## 5. 交互流程与点击预算

**服务端**（从托盘点"打开"算起）：点「服务端」→ 点「一键共享」= **2 次点击**。

**客户端**（需配对场景）：点「客户端」→ 点打印机 → 输 4 位码 → 点「连接」=
**4 次点击**（免配对场景 2 次；测试页可选 +1）。

对照 v0.3：向导内点击数本来就不多，**问题出在向导完成后**——用户被丢进一个
带 7 项侧栏、摆满 URI/指标/命令的后台控制台。v0.4 的本质改动是
**"完成后原地变主页"，并把这个主页上的每一寸都限制在 §3.3/§3.4 的元素表内**。

## 6. 可观测性（用户点名必须做扎实：检查点 / 日志 / 调试）

### 6.1 检查点全表（继承 v0.3 已实现的 24 项 + 新增 UI/DIAG 组）

约定不变：每项 = 断言 + 事件 + 用户可见反馈三件套；事件经 `pkg/logx` 落
`<stateDir>/logs/dyj.log`（logfmt、10 MB×3 轮转）；**token/PIN/带 token 的
URI 永不入日志**。v0.3 已实现的 BOOT/CFG/SHARE/PAIR/USE/DATA 各项全部保持；
下表只列 **v0.4 新增**，既有 24 项见 [调研 13 §5.2]（实施时以 13 §5.2 +
本表合并为准）：

| ID | 阶段 | 断言 | 失败处理（用户可见） | 事件 |
| --- | --- | --- | --- | --- |
| UI-1 | 首页三态 | role 判定与渲染页面一致（`config.role` → 路由） | 判定失败落未配置态（两张卡，安全侧） | `ui.route` |
| UI-2 | 服务端主页态 | 挑选态完成保存后 3 秒内进入主页态（热生效完成事件 CFG-2 已到） | 超时停留并显示"正在生效…" | `ui.share.done` |

| UI-4 | 客户端状态列 | added-printers 每行状态字段非空（ok/offline/revoked/missing） | 缺省显示"状态未知"并可重扫 | `client.status` |
| DIAG-1 | 帮助页自检 | doctor（服务端/客户端视角按角色）6+ 项全跑 | 逐项 ✓/✗ + Fix 按钮文案（人话映射表） | `doctor.run` |

### 6.2 故障树（v0.4 入口统一为：帮助页 → 常见问题）

v0.3 故障树（调研 13 §5.6）全部有效，补充新 IA 下的定位路径：
**任何异常 → 帮助页「常见问题」按症状点开 → 每条给出"先看哪条事件（服务端/
接收端各一行）+ 处理动作按钮"**。新增三条：

| 症状 | 先看 | 处理 |
| --- | --- | --- |
| 服务端主页"局域网可能看不到这台电脑"黄条 | `mdns.announce` 逐 ifname | 自检 → 防火墙一键指引 |
| 客户端列表里打印机灰掉 | `client.status` | "服务端不在线"→ 找服务端；"被移除"→ 重新配对 |
| 共享开关拨了没反应 | `share.toggle` / `cfg.rebuild` | 等 5 秒 → 红 + 自检 → 导出诊断包 |

### 6.3 诊断导出（新增，P1）

`GET /admin/api/diag/export` → `<桌面>/dyj-诊断-<日期>.zip`：
`log 尾 2000 行 + doctor 全量结果 + 脱敏后的 config（端口/主机名保留，
token/PIN/设备哈希剔除）+ 版本与系统信息`。用户只需要会"发文件"，
维护者拿到即定位——这是"自动化多 → 出错必能查"的最后一公里。

## 8. 阶段划分与验收标准

### P0：界面重构（本设计主体）

- **验收（全部为可勾选项）**：
  1. 路由断言：全产品仅 4 条路由；无侧栏；禁用词在所有页面文案中零出现
     （脚本扫 i18n 词条 + 渲染后 DOM 文本）。
  2. 服务端真机：安装器 → 托盘 → 两卡片 → 一键共享 = 2 次点击到主页态；

  3. 客户端真机：两卡片 → 点打印机 → 输码 → WPS 打出测试页 = 4 次点击；
     错码 3 次出现剩余次数提示，第 11 次失败触发锁定话术。
  4. 故障演练：防火墙关 / 服务端拔电 / 码轮换后旧码——三条均按 §6.2 故障树
     在 5 分钟内定位并恢复（对照检查点表逐条核）。

## 9. 开放问题

- **Q1 both 角色（同机既服务端又客户端）**：v0.4 默认主页 = 服务端视图，
  页脚一行"本机还装了 N 台网络打印机 →"进客户端视图。若真实使用中反馈
  密度不足再评估分栏。
- **Q2 "最近打印"的历史深度**：spooler 作业记录是否已持久化到重启后可见？
  P0 实施时确认，不持久化则标注"本次开机以来"。
- **Q3 手机/iPad 直接可见**：取决于 AirPrint（URF）声明（调研 README P0 #4
  仍未闭环），v0.4 **不承诺**；承诺范围 = 电脑端（装 dyj 客户端或任意支持
  IPP 的系统）。结论后补。
- **Q4 安装完成页"立即配置"默认勾选**（Inno `[Run]` 执行 `dyj open`）：
  建议默认勾选，省一次托盘点击；打包侧一行改动，随 P0。
- **Q5 旧 hash 重定向保留期**：至少保留两个版本，之后可移除。
